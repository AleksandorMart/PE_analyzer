# План написания дипломной работы

**Тема:** Разработка и исследование программы «Классификатор вредоносных PE-файлов» с графическим интерфейсом

---

## Этап 1. Анализ предметной области и постановка задачи

### 📚 Теория / изучение материалов

1. **Формат PE-файлов** (Portable Executable):
   - Структура: DOS-заголовок, PE-заголовок, таблица секций, импорты, экспорты, ресурсы
   - Как вредоносное ПО использует особенности PE (упаковка, обфускация, инъекции кода)
   - Материалы: официальная документация Microsoft, статьи на Medium, главы из книги *«Practical Malware Analysis»*

2. **Методы статического анализа вредоносных файлов**:
   - Признаки вредоносности: высокие энтропии секций, подозрительные имена секций, редкие комбинации импортов
   - Обзор существующих решений (YARA, VirusTotal статические анализаторы)

3. **Обзор машинного обучения для детектирования вредоносного ПО**:
   - Типы признаков (статический, динамический, гибридный)
   - Классические алгоритмы: Random Forest, Gradient Boosting, SVM
   - Метрики оценки (Accuracy, Precision, Recall, F1, ROC-AUC)

### 💻 Практика

- Установить Python, Jupyter Notebook, среду разработки (VS Code, PyCharm)
- Установить библиотеку `pefile`, попробовать распарсить несколько `.exe` файлов (легитимных) и вывести основные поля
- Найти и скачать **публичные датасеты** PE-файлов:
  - **MalwareBazaar** (abuse.ch)
  - **VirusShare** (требуется регистрация)
  - **EMBER** (Elsevier Malware Benchmark)
  - **SOREL-20M** (Sophos)
- Собрать коллекцию легитимных файлов (из `C:\Windows\System32`, с официальных сайтов ПО)

### ✅ Результат этапа
- Список структурных полей PE, которые будут использоваться как признаки
- Скачанные и подготовленные наборы данных (не менее 2000 файлов в сумме, из них ≈50% вредоносных)
- Конспект по теории

## Этап 2. Разработка модуля извлечения признаков (Feature Engineering)

### 📚 Теория / изучение

- Детальное изучение возможностей `pefile`: как получить секции, импорты, экспорты, ресурсы, контрольные суммы, энтропию
- Что такое энтропия, зачем она нужна (обнаружение упаковки)
- Категориальные признаки и их кодирование

### 💻 Практика

- Написать функцию `extract_features(filepath)`, которая возвращает словарь признаков (не менее **20–30 признаков**)

**Примеры признаков:**
```python
{
    'NumberOfSections',
    'SectionMinEntropy', 'SectionMaxEntropy', 'SectionMeanEntropy',
    'SizeOfCode', 'SizeOfInitializedData',
    'ImageBase', 'FileSize',
    'NumberOfImports', 'NumberOfExports', 'NumberOfResources',
    'SuspiciousAPICount',  # подозрительные API из списка
    'HasRelocations', 'HasDebug',  # бинарные признаки
    'IsPacked'  # эвристика: энтропия > 6.5 или мало секций и большой файл
}
```

- Протестировать на 50+ файлах, убедиться в отсутствии ошибок
- Сохранить извлечённые признаки в CSV-файл для всех образцов

### ✅ Результат этапа
- Рабочий модуль `feature_extractor.py`
- CSV-файл с признаками для всей обучающей выборки

## Этап 3. Обучение и оценка модели машинного обучения

### 📚 Теория / изучение

- Подготовка данных: масштабирование (StandardScaler), борьба с пропусками, кодирование
- Разделение выборки на train/test (стратификация)
- Подбор гиперпараметров (GridSearchCV или RandomizedSearchCV)
- Кросс-валидация
- Сравнение алгоритмов: Logistic Regression, Random Forest, XGBoost, LightGBM

### 💻 Практика

Написать скрипт `model_training.py`:
```python
# Псевдокод логики:
1. Загрузить CSV
2. Удалить некорректные строки
3. Разделить на X, y
4. Обучить несколько моделей, сравнить по метрикам
5. Выбрать лучшую модель
6. Сохранить модель и Scaler с помощью joblib
```

- Построить матрицу ошибок (confusion matrix) и ROC-кривую
- Провести анализ важности признаков (feature importance)

### ✅ Результат этапа
- Файл обученной модели `malware_model.pkl` / `.joblib`
- Файл скейлера `scaler.pkl`
- Графики и таблицы с метриками (для диплома)
- Вывод: какая модель показала лучший F1-score (например, Random Forest с F1 > 0.95)

## Этап 4. Разработка графического интерфейса (GUI) и интеграция

### 📚 Теория / изучение

- Выбор фреймворка: Tkinter (проще, встроенный) или PyQt/PySide (профессиональнее). *Рекомендуется Tkinter для скорости*
- Основы событийной модели, привязка кнопок, работа с файловым диалогом
- Многопоточность: чтобы интерфейс не зависал во время анализа

### 💻 Практика

Создать главное окно приложения (класс `MalwareClassifierApp`):

**Элементы интерфейса:**
- 🔘 Кнопка «Выбрать файл» (filedialog)
- 📄 Метка с путём к файлу
- 🔍 Кнопка «Анализировать»
- ⏳ Индикатор прогресса (`ttk.Progressbar`)
- 📝 Текстовое поле для вывода результата

**Логика работы:**
- По нажатию «Анализировать» запустить в отдельном потоке извлечение признаков и предсказание
- После завершения вывести вердикт («Безопасный» / «Вредоносный») и уверенность
- Обработать ошибки: не-PE файл, повреждённый файл, отсутствие модели

### ✅ Результат этапа
- Готовое приложение `main_app.py`, которое можно запустить и проверить на произвольных `.exe`-файлах
- Возможность видеть время анализа

## Этап 5. Тестирование и исследование эффективности

### 📚 Теория / изучение

- Методологии тестирования классификаторов: hold-out validation, тест на новой выборке (вне датасета)
- Анализ ложноположительных и ложноотрицательных срабатываний
- Оценка производительности (время анализа одного файла)

### 💻 Практика

- Подготовить отдельный тестовый набор файлов (не участвовавших в обучении)
- Запустить программу на 100+ файлах, зафиксировать результаты
- Рассчитать финальные метрики: Precision, Recall, F1, Accuracy
- Выявить наиболее частые ошибки (какие вредоносные файлы не распознаются, какие легитимные ошибочно считаются вредоносными)
- Провести атаку adversarial example (если позволяет время): попробовать модифицировать вредоносный файл (добавить пустые секции) и проверить, обманет ли это классификатор
- Измерить среднее время анализа одного файла (например, 0.5–2 секунды)

### ✅ Результат этапа
- Отчёт о тестировании с таблицами и графиками
- Выводы о сильных и слабых сторонах классификатора
- Рекомендации по улучшению (например, добавить динамические признаки или использовать ансамбль)
